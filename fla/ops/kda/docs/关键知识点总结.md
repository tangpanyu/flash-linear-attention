# 关键知识点总结

这份笔记整理读 KDA kernel 时最容易混的几个点：为什么 gate 是 `[B, T, HV, K]`，为什么要做 chunk 内 cumsum，什么时候只需要最后一行，什么时候必须保留每一行。

## 1. Gate 为什么是 `[B, T, HV, K]`

KDA 的 gate 不是每个 head 一个 scalar，而是每个 value head、每个 key channel 一个 vector gate：

```text
q/k:  [B, T, H,  K]
v:    [B, T, HV, V]
g:    [B, T, HV, K]
beta: [B, T, HV]
```

所以对固定的 batch、token、value head，`g` 仍然是一条长度为 `K` 的向量：

$$
g_{b,t,h,:}\in\mathbb{R}^{K}
$$

这条向量对应 state 的每个 key/channel 行的衰减。也就是说，同一个 token 对 state 不是只给一个统一 decay，而是给每个 key channel 一套 decay。

如果是 GDN/GLA 那种 scalar gate，常见形状可能是：

```text
g: [B, T, H]
```

但 KDA 的关键区别就是：

```text
state 的每个 key/channel 行可以有不同记忆长度。
```

## 2. `g.cumsum` 在表达什么

进入 chunk 前，`g` 是每个 token 的 log-space per-step decay。对一个 chunk 做：

```python
g = g.cumsum(-2)
```

后，得到的是从 chunk 起点到当前 token 的累计 log decay：

$$
g_r=\sum_{t=0}^{r}g^{raw}_t
$$

所以：

$$
\exp(g_r)
=
\prod_{t=0}^{r}\exp(g^{raw}_t)
$$

直觉上：

```text
g_r 表示从 S0 走到 token r 时，旧 state 的每个 key channel 总共被衰减了多少。
```

因为 `g_r` 是向量，所以这个衰减是 channel-wise 的：

$$
\exp(g_r)\in\mathbb{R}^{K}
$$

## 3. 什么时候只需要最后一行

如果只看旧 state 从 chunk 起点传到 chunk 末尾这一部分，确实只需要最后一行 gate：

$$
S_{\text{old}\rightarrow C}
=
\operatorname{Diag}(\exp(g_C))S_0
$$

代码里对应：

```python
S = S * g_last.exp()[:, None]
```

也就是说，对 `S0 -> SC` 的旧 state 衰减，`g_last` 足够。

## 4. 为什么不能只保留最后一行

kernel 还要算 chunk 内所有 token 的输出和 token 之间的写入传播，所以不能只保留 `g_last`。

第一个原因：每个 token 的输出都要读旧 state：

$$
o^{old}_r=(\exp(g_r)\odot q_r)S_0
$$

这里每个 token `r` 都需要自己的 `g_r`。

第二个原因：token `i` 的写入传到 token `r`，需要相对 decay：

$$
\rho_{r,i}=\exp(g_r-g_i)
$$

它出现在两个核心矩阵里：

$$
Aqk_{r,i}
=
q_r^\top(\exp(g_r-g_i)\odot k_i)
$$

$$
B_{r,i}
=
k_r^\top(\exp(g_r-g_i)\odot k_i)
$$

只知道 `g_last` 无法恢复任意 `g_r - g_i`。

第三个原因：当前 chunk 内每个 token 的写入传到 chunk 末尾，也需要每个 token 的 `g_i`：

$$
k_{\text{right},i}
=
\exp(g_C-g_i)\odot k_i
$$

所以 state update 是：

$$
S_C=\operatorname{Diag}(\exp(g_C))S_0+k_{\text{right}}^\top v_{\Delta}
$$

这里旧 state 部分只需要 `g_C`，但当前 chunk 写入部分需要所有 `g_i`。

## 5. 一句话区分

```text
只算旧 state 从 S0 到 SC:
  只需要 g_last。

算每个 token 的输出:
  需要每一行 g_r。

算 chunk 内 token i 到 token r 的传播:
  需要 g_r - g_i。

算当前 chunk 写入传到 SC:
  需要 g_last - g_i。
```

因此 kernel 里保留 chunk 内完整的 `[BT, K]` 累计 gate 是必要的。

## 6. `tl.gather` 那行在做什么

`chunk_kda_fwd_kernel_intra_sub_chunk` 里有：

```python
b_g = tl.load(p_g, boundary_check=(0, 1))  # [BC, BK]

b_gn = gather(
    b_g,
    tl.full([1, BK], min(BC//2, T - i_ti - 1), dtype=tl.int16),
    axis=0
)
```

这里 `b_g` 是当前 sub-chunk 的 gate tile：

```text
BC: token 维，通常是 16
BK: key/channel 维
```

`tl.gather(..., axis=0)` 等价于从 `b_g` 里取一行：

```python
row_idx = min(BC // 2, T - i_ti - 1)
b_gn = b_g[row_idx:row_idx + 1, :]
```

完整 block 时取中间 token；尾部不足 16 个 token 时取最后一个有效 token。结果 `b_gn` 的 shape 是 `[1, BK]`，后面会按 channel 广播。

注意这不是取一个 scalar，而是取一整条 gate 向量：

$$
b\_gn\in\mathbb{R}^{1\times K}
$$

## 7. 为什么可以减去这一行

后面代码：

```python
b_gm = b_g - b_gn
b_gq = exp2(b_gm)
b_gk = exp2(-b_gm)
```

这是数值稳定技巧。原本要算：

$$
2^{g_r-g_i}
$$

任选一个 reference gate $g_{ref}$，都有：

$$
2^{g_r-g_i}
=
2^{g_r-g_{ref}}\cdot 2^{g_{ref}-g_i}
$$

所以减去 `b_gn` 不改变数学结果，只是把指数输入拆成更靠近 0 的两部分，降低 `exp2` 溢出或下溢风险。

因为 KDA 的 gate 是 vector gate，这个 reference 也是逐 channel 的：

$$
g_{ref}\in\mathbb{R}^{K}
$$

也就是：

$$
(g_r-g_{ref})_c=g_{r,c}-g_{ref,c}
$$

不是一个 scalar 同时减所有 channel。

## 8. 和矩阵计算的关系

`naive_chunk_kda` 的两个关键矩阵是：

$$
B_{r,i}
=
k_r^\top(\exp(g_r-g_i)\odot k_i)
$$

$$
Aqk_{r,i}
=
q_r^\top(\exp(g_r-g_i)\odot k_i)
$$

`chunk_kda_fwd_kernel_intra_sub_chunk` 用 `b_gn` 中心化后，实际算的是：

$$
\exp(g_r-g_i)
=
\exp(g_r-g_{ref})\exp(g_{ref}-g_i)
$$

代码形式就是：

```python
b_Aqk = dot(q * exp(g - g_ref), trans(k * exp(g_ref - g)))
b_Akk = dot(k * exp(g - g_ref), trans(k * exp(g_ref - g))) * beta[:, None]
```

这和矩阵公式完全一致，只是写法更适合 Triton kernel。
